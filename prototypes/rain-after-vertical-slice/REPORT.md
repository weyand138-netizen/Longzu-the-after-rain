# 《雨停之后》垂直切片报告

## 执行摘要

**结论：PROCEED**

一名玩家在无开发者指导的情况下独立完成了“雨夜站台 → 三次语义选择 → 列车回收”的完整循环。玩家在不到 10 秒内到达第一个有效选择，并在“跟随绘梨衣的视线、从地上捡起纸条”这一刻明确感受到“先观察她未说出口的意图，而不是替她决定”的核心体验。

切片在一个制作日内完成，自动化与人工试玩均未发现阻塞。进入生产时需优先解决两项非阻塞视觉问题：缩小右上角快捷按钮，减轻正文字重。

## 验证问题

> 一个第一次接触本作的玩家，能否在五分钟内、无需开发者说明，体验到“温柔不是替她决定，而是先观察、再询问，并接受共同承担后果”；同时，我们能否在一个制作日内，以代表性品质完成一轮这样的内容生产？

### 结果

| 验证项 | 证据 | 结果 |
|---|---|---|
| 无指导完成完整循环 | 玩家独立抵达“序章完成” | 通过 |
| 两分钟内理解如何行动 | 第一个有效选择在 10 秒内出现 | 通过 |
| 核心体验成立 | 玩家主动指出“跟随视线、捡起纸条”传达了观察与尊重 | 通过 |
| 无关键体验阻塞 | 玩家报告除视觉权重外没有困惑、卡住或异常 | 通过 |
| 单人制作可行 | 玩家认为速度快于预期，当前质量对个人开发已属优秀 | 通过 |
| 代表性质量可持续 | 可行，但正式生产需略微提升视觉精度 | 有条件通过 |

## 核心循环验证

本次切片覆盖：

1. **开始**：雨夜站台，绘梨衣以视线引向被雨打湿的愿望纸。
2. **挑战**：玩家在时间压力下决定观察什么、由谁选择路线、如何面对追踪。
3. **承诺**：玩家可以选择共同决定并承担后果，而非单方面保护。
4. **回收**：列车场景通过愿望纸、车票、路线与追踪线索回收早期选择。
5. **记录**：愿望手册保存关系与观察结果，不显示好感数值。

绘梨衣的表达在试玩前完成设定校正：完整口语对白被移除，仅使用肢体语言、视线、物件操作及“嗯”等简单单音节。校正后重新通过全部测试并完成本次真人试玩。

## 体验评估

### 成立的部分

- 第一个选择出现得足够快，没有冗长的被动阅读前奏。
- “视线 → 纸条 → 玩家行动”的无声引导能够独立传达人物意图。
- 选择没有显示数值评价，但玩家仍能理解“询问”与“替她决定”的差别。
- 延迟回收能让早期行为重新出现，而不是成为一次性按钮。
- 玩家未报告流程、操作或叙事理解方面的阻塞。

### 需要提升的部分

- 右上角设置、保存等快捷按钮过大，视觉权重高于叙事画面。
- 正文字重偏粗，持续阅读时有晃眼感。
- 正式生产应把这两项固化为 UI 尺寸与字重规范，而不是逐屏微调。

## 技术发现

- Ren'Py 8.5.3 的状态、回退、持久化、选择与屏幕边界在当前循环内工作正常。
- 正式工程与垂直切片保持目录隔离；正式工程不导入 `prototypes/` 代码。
- 内容约束脚本会拒绝绘梨衣的完整口语台词。
- 测试结果：
  - 纯结局逻辑：6/6 通过；
  - 正式工程流程：2/2 通过，7/7 断言通过；
  - 垂直切片流程：3/3 通过，16/16 断言通过；
  - 正式工程与切片 lint、compile 均通过；
  - 修订后的结束页与愿望手册视觉基线已人工检查。
- 未在本切片中验证最终音频管线、角色立绘、动画 CG 或完整字体缩放。
- 本轮未记录帧时间剖析；切片以静态背景和标准 Ren'Py 过渡为主，未观察到交互阻塞。

## 经验总结

- 自动化能够证明流程和状态正确，却不能发现“人物会不会说出这种话”这一类角色真实性问题；真人试玩不可替代。
- 可读性不仅取决于是否溢出或对比度达标，按钮视觉权重与字体粗细同样会破坏注意力分配。
- 核心体验最有效的载体不是解释性对白，而是可观察动作与玩家主动回应之间的连接。
- 本次范围足够集中；如果重做，不需要扩大系统，只需要更早锁定角色表达规范和 UI 字重规范。

## 建议的下一步

1. 保留 `PROCEED` 结论，执行预制作 → 生产阶段门禁。
2. 将快捷按钮尺寸与正文字重调整列为生产首个 UI 工作项。
3. 在正式生产代码中从头实现经验证的设计，不复制或导入切片实现。
4. 补齐生产门禁所需的美术圣经、关键 UX 规格、Foundation/Core epics、stories 与首个 sprint plan。
5. 正式生产期间安排更多新玩家试玩；一次试玩满足最低门槛，但不足以代表广泛玩家。
