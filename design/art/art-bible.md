## 1. Visual Identity Statement

### One-line rule

**让玩家先看见一个人的迟疑，再看见命运的重量：冷雨中的真实空间承载未说出口的动作，暖色只留给被认真争取的普通生活。**

### Supporting principles

1. **事实先于解释**（支柱：看见未说出口的话）。当动作、视线、停顿或物件可以传达信息时，优先给画面留下可观察证据，不用旁白替角色说完。
2. **亲密感来自留白**（支柱：温柔必须被挣来）。构图保留人物之间的距离与空位；不以满屏表情、爱心、粉色滤镜或过度 UI 提示替玩家宣布“这是善意”。
3. **代价要具体，生活要发亮**（支柱：悲剧也是完整答案／用普通生活抵抗宏大命运）。结局与失败使用具体物件、路线、座位、纸张和未完成动作呈现；真结局的暖色来自一张桌子、一盏灯或一段普通日常，而不是胜利特效。

### Decision test

当两个美术方案都可行时，选更能让玩家在不读内部数值、不看路线提示的情况下，指出“她刚刚做了什么”和“这个选择留下了什么具体后果”的方案。

## 3. Shape Language

### Character silhouettes

- 人物轮廓以自然的不对称、肩线、手部动作和物件关系为辨识核心；禁止只靠发色或服装颜色区分角色。
- 绘梨衣的可读性来自“视线—手—物件”三点关系：视线先指向信息，手部决定是否接近，物件承载她无法用完整对白表达的选择。
- 路明非的姿态可更前倾、更急，但在需要让绘梨衣自主决定的时刻，画面必须给她独立的动作空间。
- 角色缩略图在 160 px 高度下仍应保留姿势差异；表情不是唯一信息通道。

### Environment geometry

- 城市与车站使用水平、垂直、重复网格（铁轨、雨棚、灯管）表达秩序与追踪压力。
- 普通生活空间使用圆角、低矮家具、桌面和可触碰的小物件降低宏大感。
- 有机形状只作为“人留下的痕迹”（湿纸、衣角、头发、树叶、水面），不把场景做成梦幻抽象空间。

### UI shape grammar

- 叙事 UI 是屏幕空间的半透明深蓝矩形，边缘清楚但不拟物化；愿望手册是米白纸页矩形，作为唯一强烈的“物件化”界面。
- 主要按钮使用大面积平面与直角/微圆角；不使用玻璃拟态、霓虹描边、金属按钮或拟真皮革。
- 焦点必须同时使用轮廓、填充/位置变化与文字状态，不得只换颜色。

### Hero vs. supporting shapes

- Hero：人物手部与视线、纸张、车票、硬币、桌面灯、列车门。
- Supporting：雨棚、栏杆、窗格、轨道、城市灯点；保持有节奏但降低纹理细节。
- 任何 UI 装饰不得比当前人物动作或选择文本更亮、更动或更大。

## 4. Color System

### Production palette

| Token | Hex | Role | Use |
|---|---|---|---|
| `rain_navy` | `#0B1826` | 雨夜底色 | 背景、遮罩、主菜单基底 |
| `station_blue` | `#24435A` | 冷静结构 | 面板、栏杆、次级按钮 |
| `steel_cyan` | `#8DCBD6` | 注意但不评判 | 焦点轮廓、当前页指示、可读性强调 |
| `lamp_amber` | `#D6A766` | 被争取的温度 | 局部灯光、重要物件反光、非警报提示 |
| `paper_cream` | `#E9DFC8` | 记忆与纸页 | 愿望手册底、结局原因卡 |
| `ink_charcoal` | `#29323A` | 纸面正文 | 纸页文字、空态文案 |
| `tea_rose` | `#C88E9D` | 人的存在 | 角色名、亲密但非奖励的情感线索 |

### Semantic color rules

- 红色不作为默认语义色。危险、失败或不可恢复状态使用“文字标题 + 琥珀/深棕边界 + 形状”表达；红色只在内容本身需要且有文本说明时出现。
- `steel_cyan` 表示“当前焦点/可继续理解”，不表示正确答案。
- `lamp_amber` 表示“此处有温度或值得注意的具体事实”，不表示奖励或更高数值。
- `tea_rose` 表示角色/人的痕迹，不表示好感度。
- “新记录”与“曾经走过”必须有文字标签；圆点或色块只能辅助。

### Area temperature rules

- 车站、雨街、追踪场景：蓝色占主导，暖色只来自真实光源，暖色面积不超过画面有效焦点的 20%。
- 学校、网吧、家庭空间：中性灰蓝为底，加入米黄/木色表面；温暖必须与具体日常物件绑定。
- 列车与海边：冷蓝向灰白过渡，出口/远景可出现低饱和金色；不使用“自由=彩虹”式直白编码。
- 红井与终局压迫空间：减少色相数量、提高局部对比，使用物件颜色差异保留因果线索。

### Accessibility backups

所有语义色必须有至少一种文字、轮廓、图标形状或位置备份。高对比模式移除纸纹/雨痕等装饰，并确保 `paper_cream`/`ink_charcoal` 与 `rain_navy`/`paper_cream` 的文字对比通过 QA 检查；具体最终字体与渲染结果以引擎实测为准。

## 5. Character Design Direction

- 绘梨衣：以宽松、可动作化的服装与清晰手部空间为原则；服装不遮挡视线、手和物件。她的安静不是“无表情”，至少通过视线、手部停顿、身体转向或物件摆放给出一个可观察变化。
- 路明非：轮廓更松散、动作更大，但在代替她决定时，画面应出现侵入她空间的具体构图后果，而不是只靠台词批判。
- 盟友/NPC：用姿态节奏、携带物件与所处光区区分；同阵营不强制同色。
- 敌对或追踪力量：优先通过遮挡、远距、重复制服/设备和切断出口构成压力，不用怪物化脸谱。
- 表演采用“少量但有意图”的姿势库：看、停、靠近、避开、递出、收回、转身。复杂意图必须由组合与上下文推断。
- LOD 以镜头可读性为先：叙事近景保留眼睛/手/物件关系；远景减少面部细节但保留姿势与空间关系。

## 6. Environment & Level Art

- 建筑语言为东京通勤空间与普通生活空间的交叠：车站钢架、广告牌、便利店/网吧桌面、学校走廊、列车座位。
- 采用“真实材质 + 克制绘画化调色”：雨面、金属、玻璃、纸张要有材质差异，但避免写实摄影式过度锐化。
- 观察型场景每个镜头至少提供一个可被忽略但能在后续回收的物件；不通过发光轮廓标出全部可观察点。
- 追踪/逃亡场景降低无关道具密度，保持路线、遮蔽物与出口可读；普通生活场景允许桌面小物增加亲密度，但不可堆满。
- 环境叙事优先顺序：物件状态 → 空间使用痕迹 → 时间变化 → 文字标识。不得用无来源的说明牌替代场景事实。

## 7. UI / HUD Visual Direction

### Screen roles

- 游戏不使用持续信息密集 HUD；叙事时只显示必要的对话/选择与低存在感的系统入口。
- 选择时采用单列、整行可点击的 choice surface；quick actions 从属于叙事，进入 critical interaction 后隐藏并移出焦点图。
- 愿望手册使用米白纸页与深色墨字，明确区别于深蓝叙事面板；不得显示五轴、完成率、隐藏条件或未来路线。
- 错误/恢复界面保持深蓝中性，安全出口优先于技术细节。

### Typography

- 中文正文使用有完整简体中文覆盖、可核验授权的无衬线字体；视觉倾向清晰、略有人文感，不使用细体或装饰书法体作为正文。
- 标题可使用同字体的较大字重；正文基线避免切片中“过重黑边”问题，描边仅用于复杂背景上的最小可读性补强。
- 目标结构：正文 34 px（1920×1080基线，实际以字体缩放换算）、角色名 36–40 px、标题 54–92 px；最小 1280×720 与 1.5 倍字体必须以 viewport/重排保留完整操作。

### Iconography and motion

- 图标为单色线性/几何图标，必须配文字；禁止用图标单独表达 save、load、danger、new record 等关键语义。
- 入场/退场以 120–220 ms 的淡入、短位移或直接切换为主；`reduced_motion` 下直接进入最终状态。
- 禁止循环漂浮、闪烁提示、镜头抖动或粒子庆祝成为信息唯一载体。结局原因卡在 reduced-motion 下使用 0 ms 文字替换。

## 8. Asset Standards

### Runtime and source

- Engine: Ren'Py 8.5.3；目标 1920×1080；1280×720 为硬布局基线；Windows 10/11 x86-64、离线运行。
- 背景资产：源文件保留 2560×1440 或更高；运行时优先使用 1920×1080 PNG/JPEG/WebP，经视觉 QA 后决定压缩格式。避免在进入场景前加载完整分辨率 CG。
- UI 尽量使用 Ren'Py primitives（Solid、Frame、text、viewport）而非大量位图切片；单个 UI 装饰图默认不超过 1024×1024。
- 纹理/背景使用低频细节与可压缩纹理，避免高频雨线、胶片噪点和大面积透明叠层。

### Naming and folders

- 资源路径：`game/assets/{backgrounds,characters,props,ui,vfx,fonts}/`。
- 文件名全小写 `snake_case`，稳定语义命名：`bg_station_platform_rain.png`、`prop_wish_paper.png`、`ui_focus_frame.png`。
- 每个外部/生成资产必须在 `docs/legal/asset-register.md` 登记来源、许可/非商业依据、原始文件名与 SHA-256；来源未知的资产不得进入生产包。

### Budgets and export

- 交互屏目标 60 fps / 16.6 ms；同屏避免超过 2 个持续全屏透明叠层、4 个大面积动态效果或无必要的逐帧动画。
- 单个背景尽量控制在运行时 8–12 MB 内；超出需有画质/内存实测记录。字体包只保留实际需要的字形子集，但必须覆盖全正文与 UI 文案。
- 角色立绘优先分层 PNG；单角色默认不超过 4 个同时可见层。导出统一 sRGB、无隐藏调试层、无未使用 alpha 边框。
- VFX 采用短时、低频、可静态替代的序列；无音频时仍必须可理解。

## 9. Style Prohibitions & Reference Direction

### Draw from

1. **雨后城市摄影的构图逻辑**：借用湿地反光、玻璃隔断与远近灯点的层次；不追求摄影级锐度。
2. **纸张手册与手写档案的触感**：借用米白底、墨色层级和局部压痕；不把手册做成解锁收集成就板。
3. **通勤剧场的空间叙事**：借用站台、列车、网吧和便利店的可重复日常路径；不把背景变成只为战斗服务的奇观。
4. **舞台留白与静止构图**：借用角色之间的空位和等待来承载关系；不把情绪都交给表情包式演出。

### Prohibitions

- 不使用恋爱游戏式好感度心形、五轴/数值/评级/路线提示、正确答案高亮或奖励式 choice feedback。
- 不使用霓虹赛博朋克、金色神圣光柱、血色全屏、过度 bloom、镜头抖动、闪烁或粒子作为默认情绪快捷键。
- 不让 UI 装饰、系统 quick actions、成就弹窗或纸纹遮挡人物动作、选择文本或因果物件。
- 不用 hover-only information、颜色-only semantics、声音-only confirmation 或需要精确指针的操作。
- 不把绘梨衣的动作转译成未经内容批准的完整内心独白；不以文字替代她的非语言表达。
- 不使用未经登记的《龙族》官方素材、字体或第三方音乐/音效。

## Production Gate

每个新资产提交必须回答：它是否加强“可观察的具体事实”？是否让普通生活与宏大命运形成对照？是否在 1280×720、字体 1.5、高对比、静音、reduced-motion 下仍可理解？任何一项为否，进入 Art/UX 复审，不得直接进入发行构建。
